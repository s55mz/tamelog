# Phase 11 記録

更新日: 2026-03-13

## ステータス

- 完了

## 目的

- フロントの既存デザインを全撤去し、デザインシステムを 1 から作り直す
- 画面遷移の共通レイアウトを新しい見た目の基準として再構築する
- 旧デザインの色、余白、カード、ナビゲーション表現を残さず差し替える

## 計画

- 既存の `AppLayout` と `styles.css` を基点に、UI 依存のクラス構成を洗い出す
- 共通レイアウトを新しいサイドバー / モバイルドック構造へ作り直す
- グローバルスタイルを全面的に書き換え、全画面が新しいデザインシステムで表示されるようにする
- 型チェックとビルドで崩れていないことを確認する

## 実行

- `client/src/components/AppLayout.tsx` を削除して、新しいアプリシェルへ置き換えた
- `client/src/styles.css` を削除して、新しいトークン、タイポグラフィ、レイアウト、カード、フォーム、ナビゲーション、モバイルドックのスタイルを 1 から書き直した
- ページ群で利用されている既存クラスを洗い出し、新デザインシステム側で再マッピングした
- `npm run typecheck` と `npm run build` を実行した

## 結果

- やったこと:
  - PC は固定左レール、SP は下部ドック + シートメニューの構造へ刷新した
  - フォント、配色、背景、角丸、ボタン、カード、フォーム、一覧 UI をすべて新しいルールへ差し替えた
  - 旧来のガラス調 / Apple 風 / DADS 風の見た目を引き継がないよう、`AppLayout.tsx` と `styles.css` を全面置換した
  - 既存ページの DOM は大きく崩さず、見た目の基盤だけを完全に再設計した
- 確認結果:
  - `npm run typecheck` 成功
  - `npm run build` 成功
- 残課題:
  - 今回は見た目の基盤刷新が中心で、ページごとの DOM 再設計までは未実施
  - さらに詰めるなら、各ページを新デザインシステム専用コンポーネントへ分割してクラス依存を減らせる

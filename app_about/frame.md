# 貯めログ ワイヤーフレーム基準書

更新日: 2026-03-12

この文書は、貯めログの最優先文書です。
画面構成、導線、画面ごとの役割、v1 で確定した判断はこの文書を基準にします。
他の文書は、この文書を補足するためだけに存在します。

## 1. アプリ全体像

### 1.1 目的

貯めログは、収支を記録するだけの家計簿ではなく、貯金を続ける行動を支援するアプリです。
特に ADHD 傾向のあるユーザーでも続けやすいように、操作を短くし、数字を見やすくし、否定的な表現を避けます。

### 1.2 v1 の前提

- 日本国内利用前提
- タイムゾーンは `Asia/Tokyo` 固定
- PC はサイドバー、モバイルはボトムナビ
- フロントと API は同一リポジトリ
- 招待制
- 管理者画面あり

### 1.3 アプリ状態遷移

1. 未セットアップ
   - `SetupWizard`
2. セットアップ済み / 未ログイン
   - `LoginPage`
   - 招待リンク経由のみ `RegisterPage`
3. ログイン済み / 初期設定未完了
   - `UserSetupWizard`
4. ログイン済み / 初期設定完了
   - 通常アプリ本体

- 淡いグレーのカード背景
- 柔らかい角丸
- 短文中心
- 数字を大きく見せる

全体トーン:

- calm playful finance app design
- friendly and approachable interface
- simple rounded shapes
- clear hierarchy
- generous spacing
- minimal visual complexity
- light and welcoming atmosphere
- motivating and rewarding tone
- modern but gentle UI
- easy to understand at a glance
- mobile-first but desktop-compatible
- subtle personality without reducing trust
- smooth and calm interaction feeling

デザインの狙い:

1. はじめに

### 4.5 ホーム `/`

役割:

- 毎日の起点
- 今の状況と次にやることを短く示す
- このアプリ独自の進捗体験を見せる

表示内容:

- 挨拶
- 注目の目標 1 件
- 注目目標の進捗画像
- 給料日バナー
- 今月の貯金進捗
- 今日のミッション
- 衝動買いチェック導線
- 最近の記録

注目目標ロジック:

基本スコア:

- `期限スコア * 0.7 + 進捗スコア * 1.0 + 優先度補正 * 0.5`

同点時:

1. 進捗が高い
2. 期限が近い
3. ランダム

今日のミッション優先順:

1. 待機終了した衝動買い項目がある
2. 今日の記録がない
3. 連続記録 3 日以上
4. その他の継続促し

#### 注目目標カードの正式構成

- 進捗画像
- 進捗画像専用テキスト
- 目標名
- 残り金額
- 現在金額 / 目標金額
- 進捗バー
- 残り日数

表示例:

```txt
[進捗画像]
旅行の準備をしよう

旅行用ノートPC
あと ¥18,400
¥21,600 / ¥40,000

進捗バー 54%
あと 84日
```

#### 進捗画像の役割

- 装飾ではなく、進捗の報酬表現
- 数字より先に感情的な理解を作る
- ホームを見る理由を増やす
- 他アプリとの差別化の中心にする
- 画像に添える短い文で行動の意味を補強する

#### 進捗画像専用テキスト

- 画像ごとに専用の短いテキストを持つ
- ホームでは画像のすぐ近くに表示する
- テキストはモチベーションを上げる短文にする
- 「〜の準備をしよう」「少しずつ近づいています」など、進捗の意味が伝わる文にする
- 目標名そのものを繰り返すだけの文にはしない

例:

- `旅行の準備をしよう`
- `新しい相棒を迎える準備をしよう`
- `暮らしを整える準備をしよう`
- `あと少しで完成です`
- `ここまで積み上がりました`

#### 進捗画像のステップ構成

画像は 5 ステップ + 達成状態で管理する。

| 進捗率 | 画像状態 | 意味 |
|---|---|---|
| 0-19% | Step1 | 設計図、構想段階 |
| 20-39% | Step2 | 骨組み、基本構造 |
| 40-59% | Step3 | 組み立て中 |
| 60-79% | Step4 | ほぼ完成 |
| 80-99% | Step5 | 完成直前 |
| 100%以上 | Complete | 達成済み特別表示 |

#### 達成時演出

- 完了ラベル
- 達成バッジ
- 短い祝福メッセージ
- 次の目標への導線

#### 画像デザインルール

- 被写体は中央に 1 つ
- 背景は透過
- 余計な小物は入れない
- 同じ構図
- 同じ角度
- 同じフレーミング
- 小さくても対象が分かる

スタイル:

- minimal vector illustration
- clean modern UI style
- pastel colors
- soft shadows
- transparent background
- icon-friendly
- consistent angle
- consistent framing
- playful flat illustration base
- slightly bold outline style
- minimal visual complexity
- reward-oriented visual feedback

UI とイラストの統一ルール:

- UI 側は線を強くしすぎない
- 太めアウトラインは主に進捗画像側で使う
- カード、ボタン、バッジはやわらかく整理し、幼すぎない見た目にする
- イラストの雰囲気と UI の配色、角丸、余白感を揃える
- アプリ全体で同じ visual language を保つ

#### 画像選定ルール

- ユーザー入力の目標名と、画像管理用カテゴリは分ける
- 目標作成、更新時に AI が `category` と `subcategory` を自動推定する
- AI が失敗した場合は `other/generic`
- ユーザーは後から画像カテゴリを手動修正できる

#### テーマ

- ユーザーは画像テーマを選べる
- テーマで変わるのは質感、雰囲気、演出トーンのみ
- 構図、進捗段階、分かりやすさは固定

#### フォールバック

- 画像が未生成、未配置、読込失敗時は `default_generic_step1-5` と `default_generic_complete` を使う
- 専用テキストが未設定ならカテゴリ共通テキストを使う
- それも無ければ `目標に向けて少しずつ進んでいます` を使う

- 10%

- 50%
- 75%
- 90%
- 100%

### 4.6 記録 `/record`

役割:

- 最短で 1 件の記録を完了させる

種別:

- 収入
- 支出
- 貯金
- 移動

入力項目:

| 種別 | 必須 | 任意 |
|---|---|---|
| 収入 | 金額、口座、日付 | カテゴリ、メモ |
| 支出 | 金額、口座、日付 | カテゴリ、メモ |
| 貯金 | 金額、口座、日付 | 目標、メモ |
| 移動 | 移動元、移動先、金額、日付 | メモ |

入力方針:

- 金額入力優先
- よく使う口座はデフォルト選択
- 金額 0 は不可
- 移動元と移動先は同一不可

編集方針:

- v1 で記録編集を許可する
- 種別変更も許可する
- 編集時は旧記録を打ち消してから新内容を適用する考え方でトランザクション処理する

### 4.7 目標 `/goals`

- 目標一覧
- 新規作成
- 編集
- 削除
- 達成率
- 進捗バー
- 詳細シート

目標仕様:

- 必須はタイトルと目標金額
- 期限は任意
- 進捗は `GoalRecord` の合計で計算する
- 目標には進捗画像用の `category` `subcategory` `theme` を持つ
- 作成時に AI がカテゴリを提案し、ユーザーが修正できる

### 4.8 進捗 `/progress`

タブ:

- 概要
  - 支出カテゴリ上位
- 推移
  - 過去 6 期間の収入、支出、貯金
- AI 分析
  - 月選択
  - 分析生成

OpenAI 未設定時:

- AI 分析は案内表示のみ
- 他タブは通常利用可

### 4.9 家計簿 `/ledger`

- 日付順一覧
- 合計カード

### 4.10 口座管理 `/accounts`

- 総残高
- 口座一覧
- 追加
- 編集
- 削除
- 口座間移動
- 直近移動履歴

口座種別:

- 銀行口座
- 現金
- クレジットカード

決定事項:

- クレジットカードの `balance` は「現在の未払い利用額」を正の数で持つ
- 口座一覧ではクレジットカードは「利用中」と分かる表示にする
- 記録が紐付く口座は削除不可とする

### 4.11 衝動買いチェック `/impulse`

- 商品名
- 価格
- ひとことメッセージ
- 登録から 24 時間待機
- `買った` `見送った` の判定
- 待機中一覧
- 判定済み履歴

決定事項:

- 判定時刻は JST 基準
- 待機終了前は購入判定不可

### 4.12 AI 相談 `/chat`

- 家計状況を踏まえた短い相談応答
- 返答は 3 から 5 文
- 前向き
- 否定的でない
- 数字を含める

## 5. 業務ルール

### 5.1 認証

- メールアドレス + パスワード
- JWT 有効期限 7 日
- v1 は LocalStorage 保存
- 多端末ログイン許可
- ログアウトはクライアント側トークン破棄で対応

### 5.2 パスワード

- 最小 8 文字
- 英字、数字、記号のうち 2 種類以上を含む

### 5.3 招待制

- 招待トークン必須
- 発行時にメールアドレスを固定
- 有効期限 7 日
- 1 回利用で失効
- 管理者は未使用招待を手動失効できる

### 5.4 期間管理 `periodId`

- `periodId` は `YYYY-MM-DD`
- 記録作成時に確定保存
- 給料日変更後も過去の `periodId` は変えない
- 存在しない給料日はその月の末日に丸める

例:

| 給料日 | 記録日 | periodId |
|---|---|---|
| 1日 | 2026-03-01 | `2026-03-01` |
| 15日 | 2026-03-10 | `2026-02-15` |
| 25日 | 2026-03-20 | `2026-02-25` |
| 31日 | 2026-02-28 | `2026-01-31` |

### 5.5 記録、残高、目標進捗

- `DailyRecord` は収入、支出、貯金を持つ
- `AccountTransfer` は口座移動を持つ
- すべての作成、編集、削除はトランザクションで処理する
- `Account.balance` は保持する
- `Goal.currentAmount` は持たない
- 目標進捗は `GoalRecord` の合計で計算する

### 5.6 カテゴリ

- 収入カテゴリと支出カテゴリは分ける
- デフォルトカテゴリはユーザー作成時に複製する
- v1 ではカテゴリに名前、種別、表示順、アイコンを持たせる
- 色設定は v1 範囲外

### 5.7 通知

- v1 はメール通知のみ
- Web Push は v1 範囲外
- 毎日リマインダーは 20:00 JST
- 週次レポートは日曜 19:00 JST
- 赤字アラートは「今期間の支出 > 今期間の収入」で送る

### 5.8 AI

- v1 の AI 機能は `AI 相談` と `AI 分析`
- 目標分類 AI は v1 範囲外
- 送信データは今期間の集計、主カテゴリ、目標概要まで
- 家計の生データ全文は送らない
- 利用制限は 1 ユーザーあたり 1 日 20 回
- AI 相談履歴は保存しない
- AI 分析結果は保存する

### 5.9 運用

- 本番構成に Raspberry Pi を使ってもよいが、正式な必須要件にはしない
- DB バックアップは 1 日 1 回
- 障害復旧手順は `DEPLOYMENT.md` に持つ

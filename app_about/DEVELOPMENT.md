# 開発メモ

この文書は、仕様書を見ながら実装へ進むための最低限の運用ルールをまとめたものです。
詳細仕様は `REQUIREMENTS.md` を参照します。

## 1. 先に見る文書

1. `app_about/REQUIREMENTS.md`
2. `app_about/CONCERNS.md`
3. `app_about/DEPLOYMENT.md`

## 2. 開発の基本方針

- 仕様の基準は常に `REQUIREMENTS.md`
- 新しいメモを増やす前に、既存文書へ統合できるか確認する
- 画面単位で実装しつつ、業務ルールは画面より先に固定する
- MVP から外すものは、先に明記してから後ろへ送る

## 3. 実装の進め方

推奨順:

1. データモデル確定
2. 認証とセットアップ
3. 口座
4. 記録
5. 家計簿
6. 目標
7. ホーム
8. 進捗
9. 管理者機能
10. 追加機能

## 4. 仕様変更ルール

- 画面仕様を変える前に `REQUIREMENTS.md` を更新する
- 未確定事項は `CONCERNS.md` に追加する
- README は入口に徹し、詳細仕様を書きすぎない

## 5. Git 運用

よく使うコマンド:

```bash
git status
git diff
git add <file>
git commit -m "feat: ..."
git log --oneline
```

ルール:

- 仕様変更とコード変更は可能なら同じコミットにまとめる
- 不要な Markdown を増やさない
- 大きな設計変更はコミット前に文書を先に更新する

## 6. ブランチ方針

- `main`: 安定状態
- `feature/*`: 機能追加
- `fix/*`: 修正
- `docs/*`: 文書整理

## 7. 最低限の確認項目

- 仕様書と実装が食い違っていないか
- API 名とテーブル名が統一されているか
- `periodId` と残高更新がトランザクション前提になっているか
- 管理者専用機能が一般ユーザーに見えていないか

# TameLog — 最終 UI 更新計画

更新日: 2026-03-21

---

## 0. この計画の結論

TameLog の最終 UI 方針は、単なる「入力しやすい家計簿」ではなく、
**外部で起きたイベントを候補として受け取り、1 件ずつ確定できる家計簿 UI** にすることです。

前提:

- 家計簿アプリとして、最終的な記録は 1 件ずつ持つ
- 銀行 API の本格自動連携は前提にしない
- PWA 制約を受け入れる
- VPN / Push / OCR / AI / メール転送を活かす

つまり、UI の中心は「入力フォーム」ではなく次の 2 本柱になります。

1. 手動で最速入力できる `クイック記録`
2. 外部イベントを整理する `候補インボックス`

---

## 1. プロダクトの再定義

### 1.1 旧方針

- アプリを開く
- 取引を思い出す
- 手で 1 件ずつ入力する

### 1.2 新方針

- 外部で起きたイベントを拾う
- 候補として UI に積む
- ユーザーは確認・修正・無視をする
- 最終的に 1 件ずつ正式記帳する

### 1.3 UI の役割

UI は次の 3 つを担う。

1. 今日やるべきことを 1 つ示す
2. 候補を迷わず確定させる
3. 手動入力も 10 秒以内で終わらせる

---

## 2. 設計思想

### コアコンセプト

> 開かなくても候補は溜まる。開いたときは、迷わず 1 件ずつ片づけられる。

### 3 原則

```text
1. 記録の正確性
   正式帳簿は 1 件ずつ残す。AI は補助役であり、正としない

2. 行動の軽さ
   ゼロから入力させるより、候補を確認させる

3. 現在地の明快さ
   今日の未整理件数、今日の記録数、今期の状況を最上段に出す
```

### ADHD を含む継続性への対応

| 課題 | UI 対応 |
|------|--------|
| 先送り | ホームに「今日の未整理件数」を出す |
| 思い出せない | メール / VPN / OCR 由来の候補をインボックスに積む |
| 作業記憶の負荷 | 候補カードに必要な情報だけ出す |
| 入力が重い | 手動入力は金額優先、候補確認は 3 アクション以内 |
| 報酬が弱い | 確定件数、未整理ゼロ、ストリークを即時表示 |
| 浪費衝動 | VPN 起点の保留 / 見送り導線をインボックスに統合 |

## 7. 候補確認シート / 詳細画面

### 7.1 設計思想

候補をタップしたら、ゼロからフォームを書くのではなく、
**足りないところだけ埋める**。

### 7.2 入力パターン

#### A. 高信頼候補

```text
表示:
  金額
  日時
  取引先
  推定カテゴリ
  口座

主操作:
  [この内容で確定]
  [少し修正]
  [無視]
```

#### B. 要入力候補

```text
足りないものだけ出す:
  金額
  種別
  カテゴリ

主操作:
  [確定]
```

#### C. VPN 候補

```text
主操作:
  [買った]
  [見送った]
  [24時間保留]

買った場合のみ:
  金額入力 -> 正式記帳へ
```

### 7.3 UI ルール

- 1 画面で完了する
- スクロールを最小化する
- 編集可能部分と AI 提案部分を分けて見せる
- 「この候補をどうするか」を最優先で見せる

## 9. 家計簿ページ

### 9.1 設計思想

家計簿は「正式に確定したものだけを見る場所」。
候補と混ぜない。

### 9.2 役割

- 確定済み記録の確認
- 削除 / 編集
- 期間比較
- CSV

### 9.3 UI 変更点

- 候補状態のものは出さない
- 必要なら `source` バッジだけ付ける
  - 手動
  - メール確認済み
  - OCR確認済み
- 期間サマリーは継続

- AI 月次レポートは「読めば整理できる」役割にする

## 12. AI相談ページ

### 12.1 役割変更

AI相談は「何でも聞ける場所」から、
**整理を助ける場所** に少し寄せる。

### 12.2 やること

- 候補インボックスの要約
- メール由来候補の説明
- 取引先名の意味づけ
- 「これどのカテゴリ？」の補助

### 12.3 やらないこと

- 家計簿の正本を AI チャットだけで作ること
- 記録確定のブラックボックス化

- メール / VPN / OCR を候補に集約
- AI は整理補助

### 採用しない

- 銀行 API 前提の体験
- AI 完全自動記帳
- 候補と正式帳簿の混在
- 「アプリを毎回開いて全部思い出して入力する」前提

## 19. 最終イメージ

最終的な TameLog の UI はこうなる。

> 外部で発生したイベントは候補として勝手に溜まる  
> ユーザーはホームかインボックスで、今日やるべき確認だけをする  
> それでも正式な家計簿は 1 件ずつ正しく残る

つまり、

- 家計簿としての厳密さは保つ
- 手入力の重さは減らす
- PWA 制約の中でも継続しやすい

この 3 つを同時に狙う最終更新計画とする。

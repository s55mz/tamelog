#### `tamelog-dns.service` — DNSフィルタリングサーバー

- 起動: `python3 /var/www/tamelog/tamelog-dns.py`
- ポート: `53` (UDP/TCP)
- 役割: VPNクライアントのDNSクエリを監視し、ブロックリストと照合
- 上流DNS: `1.1.1.1` (Cloudflare)
- ブロック時: `160.251.203.86` (自サーバー) に向ける → ブロックページ表示
- APIと連携: `/api/vpn/internal/active-blocks` でブロックリスト取得
- キャッシュTTL: 5秒
- 内部シークレット: `tamelog-internal-2026`

---

#### `tamelog-block-https.service` — HTTPSブロックページ

- 起動: `mitmdump --mode reverse:http://127.0.0.1:8181 -p 4443`
- ポート: `4443`
- 役割: ブロックされたHTTPSサイトへのアクセスをインターセプトし、ブロックページを表示
- 証明書: `/etc/mitmproxy/` (mitmproxy CA証明書セット)
- 設定ファイル: `/etc/mitmproxy/mitmproxy-ca*.pem|p12|cer`

---

#### `tamelog-mitm.service` — 透過型MITMフィルタ (非アクティブ)

- 起動: `mitmdump --mode transparent -p 8080 -s /var/www/tamelog/mitm-filter.py`
- ポート: `8080`
- 役割: 透過プロキシとしてHTTP/HTTPSトラフィックをフィルタリング
- 注: 現在 `running` リストにないため無効または未起動状態

## 4. 再構築手順

### STEP 0: 事前に保存すべきデータ (初期化前)

```bash
# データベースダンプ
pg_dump -U tamelog tamelogdb > /tmp/tamelogdb_backup.sql

# 環境変数
cp /var/www/tamelog/server/.env /tmp/server_env_backup.txt

# Cloudflare Tunnel認証情報
cp /root/.cloudflared/*.json /tmp/
cp /etc/cloudflared/config.yml /tmp/

# VPN認証情報
cp /etc/ipsec.d/eap-users.secrets /tmp/
cp /etc/ipsec.d/certs/vpn-server.cert.pem /tmp/
cat /etc/ipsec.secrets > /tmp/ipsec_secrets_backup.txt

# mitmproxy証明書
cp -r /etc/mitmproxy/ /tmp/mitmproxy_backup/

# DKIM秘密鍵
cp /etc/opendkim/keys/finance-pro.space/mail.private /tmp/
cp /etc/opendkim/keys/finance-pro.space/mail.txt /tmp/

# フロントエンドビルド
cp -r /var/www/tamelog/frontend/ /tmp/frontend_backup/

# Prismaスキーマ
cp /var/www/tamelog/server/prisma/schema.prisma /tmp/

# サービスファイル
cp /etc/systemd/system/tamelog-*.service /tmp/
```

### STEP 2: SSHセキュリティ強化 (最優先)

```bash
# SSH鍵認証のみに変更
sed -i 's/^PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
sed -i 's/^#PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart sshd

# fail2ban強化設定
cat > /etc/fail2ban/jail.local << 'EOF'
[sshd]
enabled = true
maxretry = 3
bantime = 86400
findtime = 600
EOF
systemctl restart fail2ban

# UFWファイアウォール
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 500/udp   # IKEv2
ufw allow 4500/udp  # IKEv2 NAT-T
ufw enable
```

## 6. セキュリティ強化 (今回の教訓)

| 対策 | 理由 |
|------|------|
| SSHパスワード認証を完全無効化 | 今回の侵入原因 |
| rootへの直接SSH禁止 (`PermitRootLogin no`) | 権限昇格のリスク軽減 |
| fail2ban の maxretry を3回に設定 | ブルートフォース耐性向上 |
| 不要ポートをUFWでブロック | 攻撃面の縮小 |
| 定期的な `ps aux` と `/etc/crontab` の目視確認 | 早期発見 |
| Cloudflare Tunnel のみで公開 (ポート80/443をUFWで閉じる選択肢) | 直接アクセスの遮断 |
